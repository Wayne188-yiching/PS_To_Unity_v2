01 · FEATURES

能做到什麼

圖層自動轉成 Unity 元件

文字圖層→ TextMeshPro保留內容、字型、字級、顏色
圖片圖層→ Image ＋ Sprite每層輸出一張 PNG
群組→ RectTransform 階層結構與座標一層對一層
遮罩→ RectMask2D ／ Mask矩形自動用 RectMask2D

命名標記加功能 寫在圖層名稱裡

  • [SCROLL_V][SCROLL_H]捲動區 ScrollRect
  • [SCROLLBAR_V][SCROLLBAR_H]可拖動捲軸
  • [GRID][V][H]自動排版 LayoutGroup
  • [SLICED=32]九宮格拉伸
  • [MASK]異形遮罩
  • [SOFTMASK_BOTTOM=64]捲動區底邊柔化
  • [MERGE]整組合成一張圖
  • [PNG]文字改輸出為圖片
  • [CG]整組淡入淡出 CanvasGroup
  • BTN_名稱開頭自動掛 Button

匯出與生成時自動處理

  • 中文圖層名 依詞庫自動翻成英文
  • 相同像素的 PNG 自動合併成一張
  • Sprite Atlas 依語系建立 Base／CHS／CHT／EN
  • 多字型 依對應表套用各自的 TMP 字型
  • 批次匯出 多份 PSD 一次輸出各自的 Package
  • 檢查 Layout 生成前檢查 Layout，列出缺少的設定

生成之後

  • Font Replacer 一鍵換字型，排版不動
  • 字型資產 從 .ttf／.otf 一鍵建 TMP Font Asset
  • SkinTheme 整套換圖，可預覽、可還原
  • 一鍵更新 PS 與 Unity 端直接從 GitHub 更新工具
AGENT SKILL

交給 Codex／Claude 自動執行：檢查 PSD → 匯出 → 驗證 → 生成 Prefab。

02 · WORKFLOW

工作流

  1. 1

    PHOTOSHOP

    整理圖層

    圖層用英文命名，需要的功能加上標記；中文 PSD 先跑自動命名。

  2. 2

    PHOTOSHOP

    匯出 Package

    1. 選單「檔案 › 指令碼 › PS To Unity v2」
    2. 點 UI Package Exporter
    3. 設定輸出位置，按「匯出 UI Package」

    產出：PNG ＋ layout.json

  3. 3

    UNITY

    設定並生成

    1. 選單「Tools › Photoshop UI Importer › Importer_v2」
    2. 套用 Package，按「建立專案資料夾」，指定 TMP 字型
    3. 按「檢查 Layout」，再按 Generate Prefab
  4. 4

    UNITY

    完成 Prefab

    1. Sprite Atlas 自動打包在 Atlas 資料夾
    2. Prefab 生成在 Prefab 資料夾

    可直接換字、換圖、做動畫、串接程式。

可重複執行 PSD 更新後重跑 2 → 3，Prefab 同步更新。

04 · COMPARISON

新舊流程，各有取捨

同一份 PSD 製作 Unity UI 時，兩種方法的交付與修改方式不同；最後都需要檢查實際畫面。

使用這套工具

優點
批次匯出圖片與版面資料，生成可編輯的 Sprite、TMP 與基本 uGUI 階層。改稿可沿用相同流程，並先用 Validate 檢查部分缺漏。
缺點
需先整理圖層、命名標記與字型對應；遇到警告、特殊視覺效果或互動邏輯，仍需人工檢查與補作。

傳統手動重建

優點
開發者可直接依專案架構安排共用 Prefab、列表模板、腳本與互動，並逐項調整特殊畫面。
缺點
切圖、命名、量座標、建立文字與階層都要重做；改稿時也需重新對照 PSD，容易累積重複工作與手動輸入誤差。

目前沒有可公開查證的節省工時數據；以上比較的是流程與工作內容。

05 · BOTTLENECKS

目前的開發瓶頸

工具能重建畫面，但要將產物接入正式 UI，仍有需要校準、整理與人工判斷的環節。

文字與特效還原

Photoshop 與 TMP 的仿粗體、字距、描邊幾何可能不同；Screen 混合模式也無法直接等同 Unity 的一般混合。正式字型與特效仍需逐案校準。

可維護的頁面結構

生成畫面可能保留靜態重複節點，未接上專案既有的共用 Prefab、列表模板與腳本。需先整理 PSD 結構，或在 Unity 進一步加工。

端到端自動化

Photoshop 與 Unity 已可串接，但命名標記、警告處理及最後畫面檢查仍需人判斷；中斷恢復與跨專案穩定性也需持續驗證。

換皮工項：新舊圖片盡量同名

相同用途的新圖與舊圖，請在製作前統一檔名。同名 PNG 可由換皮掃描直接配對並批次覆蓋，操作最順；若檔名不同，仍可用 SkinTheme 建立舊 Sprite 到新 Sprite 的對照，但需要額外設定與檢查。
