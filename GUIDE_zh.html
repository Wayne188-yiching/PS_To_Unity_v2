1. 這個工具在做什麼？

美術在 Photoshop 把一張介面排好之後，接下來本來要有人在 Unity 裡一張一張切圖、一個一個把位置擺回去，一個複雜頁面可以花掉大半天。這個工具就是把這段手工活自動化：PSD 丟進去，Unity 能直接用的介面出來。

它幫你做三件事：

Photoshop 裡的東西到 Unity 變成什麼
一般圖層（按鈕、背景、圖示…）一張 PNG 圖片，並且擺在正確位置
文字圖層還能繼續改字的文字元件，不是壓死的圖片
圖層的位置、大小、對齊方式自動換算成 Unity 的座標與對齊設定

整個流程長這樣：

你的 PSD→ 在 PS 按匯出→ 一包圖片 ＋ 一個 JSON→ 在 Unity 按匯入→ 做好的介面

所以你會用到兩端的工具：Photoshop 裡一個、Unity 裡一個。下一節先把它們裝起來。

看到不懂的名詞？點開有小抄Prefab、Sprite、TMP、Atlas、Anchor 是什麼
名詞白話解釋
PrefabUnity 的「做好的成品」。這個工具最後產出的就是它——一個可以直接拖進場景用的介面。
SpriteUnity 裡「拿來當畫面用的圖片」。你的每個 PS 圖層匯出後就是一張 Sprite。
TMP（TextMeshPro）Unity 的文字元件。文字圖層會變成它，所以之後還能改字、改顏色。
Atlas（圖集）把很多小圖打包成一張大圖，讓遊戲跑得更順。工具會自動幫你建好。
Anchor（錨點）決定這個元素「黏在畫面的哪裡」。例如黏右上角的話，換成寬螢幕時它會跟著跑到右上角。
Package（包）PS 匯出的成果，就是「一個裝滿 PNG 的資料夾 ＋ 一個 JSON 檔」。Unity 端要選的就是這包。
Layout JSON記錄「哪張圖放哪裡、多大、什麼文字」的清單檔。Unity 靠它把畫面還原出來。

2. 安裝（只要做一次）

兩邊都要裝，但都只要做一次。之後工具有新版，是用工具裡的按鈕更新，不用再重裝一遍。

PS　Photoshop 端

你不需要手動複製任何檔案。把倉庫資料夾（PS_To_Unity_v2）放在硬碟上一個之後不會再搬動的位置，然後跑一次安裝器就好，複製的事情安裝器會做。
步驟
  1. 把倉庫資料夾放到固定位置（例如 D:\Tools\PS_To_Unity_v2）。
  2. 打開 Photoshop，點選單 檔案 > 指令碼 > 瀏覽…。
  3. 選倉庫裡的 PhotoshopExporter\InstallPhotoshopPlugin.jsx，跳出成功訊息即可。
  4. 關掉 Photoshop 再重開。

重開後選單會多出一個 檔案 > 指令碼 > PS To Unity v2，點下去是一個工具面板，所有功能（匯出、自動命名、Spine、校準板、更新）都從這裡進。

Windows 常見卡關：安裝器要用系統管理員身分跑一次

如果 Photoshop 裝在 C:\Program Files\（多數人都是），一般身分寫不進去，安裝會失敗。做法：關掉 Photoshop → 對 Photoshop 捷徑按右鍵 →「以系統管理員身分執行」→ 照上面步驟跑一次安裝器 → 關掉，之後用平常方式開就好。只有安裝這一次需要。

想確認有沒有真的裝好，去看 C:\Program Files\Adobe\Adobe Photoshop <版本>\Presets\Scripts\ 裡面有沒有 PS To Unity v2.jsx。有就是成功了。

Unity　Unity 端

把整個 Assets/Editor/PhotoshopUiImporter/ 資料夾複製到你的 Unity 專案的 Assets/Editor/ 底下，Unity 會自己編譯。完成後從選單開啟：

Tools > Photoshop UI Importer > Importer_v2
開始前先確認：Unity 專案要先裝 TextMeshPro（Package Manager 搜尋 TextMeshPro 安裝即可），不然文字沒辦法產生。
複製資料夾只有第一次要做，而且是每個 Unity 專案各做一次。之後工具出新版，在 Importer_v2 視窗標題列點「從 GitHub 更新工具」就會自己抓新版覆蓋，不用重新複製、也不用重新下載倉庫。
安裝器到底做了什麼？（想知道再看）為什麼不能直接把整個資料夾複製進 Scripts

安裝器只在 Photoshop 的 Presets\Scripts\ 放兩個小檔案：一個叫 PS To Unity v2.jsx 的啟動器，和一個記住倉庫位置的設定檔。工具本體全部留在倉庫資料夾裡。

所以：更新工具不用重裝，只有搬動倉庫位置時要再跑一次安裝器（因為設定檔記的路徑失效了）。

舊版說明的裝法請改掉（只影響 v2.6.1 之前裝過的人）

舊版說明要你把整個 PhotoshopExporter/ 資料夾複製進 Presets\Scripts\，那會讓每支腳本各佔一個選單項，而且工具更新後選單裡的還是舊複本。現在不需要、也不應該這樣做。

若你之前這樣裝過，重新跑一次安裝器就好：v2.6.1 起安裝器會自動清掉散落在 Scripts 資料夾裡的工具複本（只刪本工具的已知檔名，不動其他腳本）。注意安裝器要從倉庫執行，從 Scripts 資料夾裡的複本執行會被擋下。

另外還有一種用法：完全不安裝，每次都用 檔案 > 指令碼 > 瀏覽… 直接選 PhotoshopUiPackageExporter.jsx。選單裡不會有入口，適合只偶爾用一次的情況。

開啟路徑：Tools > Photoshop UI Importer > Importer_v2

1. Photoshop UI Package

選擇 Photoshop 匯出的 Package 根資料夾，點「套用 Package」。工具自動掃描找出 layout JSON（優先找 layout.json，其次找 *_layout.json）以及 PNG 圖片資料夾。按「只驗證資料」可在不生成 Prefab 的情況下確認資料正確。

2. Unity 生成位置

填寫「專案資料夾名稱」（例如 Setting_Page），有兩個按鈕可用：

  • 「建立專案資料夾」（新專案建議用）：自動建立完整子目錄結構、生成 SpriteAtlas，並填入輸出路徑。
  • 「套用標準輸出路徑」（既有資料夾用）：只填入 Atlas 與 Prefab 路徑，不建立資料夾。

圖片來源若已在 Unity 專案 Assets 底下，工具直接使用來源路徑，不重複複製。「參考解析度」預設自動跟隨 Layout JSON 中的 Canvas 尺寸。

4. 執行

  • Validate：讀取 Layout JSON，驗證節點數量與資料格式。
  • 預覽（Dry-run）：顯示節點數、是否含文字、圖片資料夾狀態與預計輸出路徑，不執行任何操作。

4. 圖層命名：先記這幾個就好

這個工具靠圖層名稱來判斷你的意圖。在名稱裡加幾個標記，Unity 那邊就會自動做對應處理——不加也能用，只是有些事要自己補。下面五個是日常最常用的，其他的等真的需要再查。
在圖層名稱裡加效果什麼時候用
IGNORE_這層完全不匯出參考線、草稿、暫時不要的東西
BTN_Unity 自動幫它加上按鈕元件這張圖是按鈕
[SLICED=32]設成九宮格，拉大不會變形對話框底、按鈕底這種會被拉伸的圖
[H] 或 [V]（加在群組上）群組內容自動排成一排／一列並排的按鈕列、上下排列的選單
ANCHOR_TR（或 TL／BL／BR…）固定黏在畫面的某個角落右上角的關閉鈕、左上的返回鍵
沒加標記也沒關係：工具會照圖層在畫面裡的位置自動推斷對齊方式，位置一樣會對。標記只是讓你在需要時能明確指定。

特殊前綴與標記

前綴 / 標記作用
IGNORE_ 或 [ignore]匯出時完全跳過此圖層。
REF_參考用圖層，匯出時跳過。
IMG_圖片前綴（前綴本身會從 PNG 檔名中移除）。
TXT_文字前綴（前綴本身會從節點名稱中移除）。
BTN_ v2.4.3圖片節點以 BTN_ 開頭時（不分大小寫），Unity 匯入後自動在該 GameObject 加上 Button 元件，省去手動加掛步驟。
[SLICED=32] / [SLICED=左,上,右,下] v2.12.4圖片匯出時把九宮格 Border 寫入 JSON；Unity 自動套用 Sprite Border，並把生成的 Image Type 設為 Sliced。可用別名 [9SLICE=…]、[9S=…]。
[SOFTMASK_BOTTOM=64] v2.12.5搭配 [SCROLL_V] / [SCROLL_H] 使用；Unity 以雙層原生 RectMask2D 只柔化捲動視窗底邊，不增加 runtime 套件。[SOFTMASK_Y=64] 保留為相容別名。
[MASK] v2.13.0標在群組的直接子圖層上，該層形狀成為整個群組的裁切遮罩。Unity 掛 Image + Mask（showMaskGraphic 關閉＝形狀本身不顯示），群組 rect 跟著遮罩圖的範圍，遮罩層本身不生成節點。只有非矩形（圓角／圓形／不規則）才需要：純矩形的 PS 圖層遮罩會自動掛更省的 RectMask2D，而 Mask 每層多兩個 draw call。不支援用在 [SCROLL_*] 上。
[SCROLLBAR_V] / [SCROLLBAR_H] v2.13.0作為對應 Scroll 群組的直接子群組；其直接圖片子圖層以英文命名並分別加 [TRACK]、[HANDLE]。Unity 自動掛上 Scrollbar、建立保留 PS 內距的 SlidingArea，並接回父層 ScrollRect。滑軌節點不會計入 Content bounds 或 Layout。
[MERGE] v2.12.4加在群組名稱中，將群組目前可見的內容合成一張 PNG；Unity 端只建立一個 Image 節點，不保留子階層。文字、圖層效果與遮色片會一併烘入圖片。若同時存在 [H]、[V]、[GRID]、[CG] 或 Scroll 標籤，以 [MERGE] 為優先。

文字圖層輸出控制

個別圖層可在名稱中指定輸出方式，覆蓋對話框的預設設定：

名稱中含效果
[PNG] [IMAGE] [IMG] TXTIMG_強制輸出為 PNG 圖片
[TMP] [TEXT] TMP_ TXT_強制保留為 TMP 節點
九宮格圖片怎麼設[SLICED] 的數字怎麼填 
IMG_panel_[SLICED=32]
IMG_dialog_[SLICED=24,40,24,32]

單一數值代表左、上、右、下都使用相同像素；四個數值的順序固定為「左、上、右、下」。Border 以匯出 PNG 的像素為單位。若圖層未加標記，Unity 不會覆蓋 Sprite Editor 內原有的 Border；只要 Sprite 已有非零 Border，產生 Prefab 時仍會自動改用 Image.Type.Sliced。

5. 進階功能（需要時再點開）

這一整節都是折疊的。你不需要現在看，等真的遇到「我想讓這排按鈕自動排列」「這個字的外框要跟設計稿一樣厚」這類需求時，再點開對應的那一塊就好。
讓群組自動排列（Layout Group）一排按鈕、一列選單想要自動等距

圖層群組可透過明確命名標記轉為 Unity 的 HorizontalLayoutGroup 或 VerticalLayoutGroup，並自動套上 ContentSizeFitter。未標記的普通群組會完整保留 Photoshop 座標，不再猜測排版方向。

偵測規則

v2.10.1 起只接受明確命名標記，避免一般群組因子層剛好同 X/Y 而被錯誤重排：

方式條件結果
命名標記群組名稱含 [H] 或 [HLAYOUT]（不分大小寫）強制水平 layout
命名標記群組名稱含 [V] 或 [VLAYOUT]（不分大小寫）強制垂直 layout
無標記任何一般群組普通群組，不加 Layout Component，保留 PS 座標

Spacing / Padding 自動計算

  • Spacing：依子層排序後，計算相鄰子層的像素間距，取中位數作為 spacing。
  • Padding：群組邊界與最外層子層邊界的距離，分別套用到 Left / Right / Top / Bottom。
  • 所有值由 PS 設計稿座標自動算出，不需手動輸入。
v2.4.2 起停用自動去重：先前依「相同寬高」判斷重複圖會誤判（譬如同寬度但不同字的文字、同尺寸但不同 icon），而且共用後還會干擾 Layout Spacing 的中位數計算、造成排版錯誤，故 v2.4.2 起每個圖層各自輸出獨立 PNG。若需要圖片共用，請在 PS 將圖層名稱統一（如 btn_bg ＋ 副本），工具會以 btn_bg_002、btn_bg_003 的方式分別匯出，仍可由設計師後續手動合併或在 Unity 端用相同 Sprite。
把一個群組壓成單張圖（[MERGE]）背景裝飾、複雜特效不想在 Unity 拆成幾十層

在群組名稱加上 [MERGE]，工具會把群組目前可見的內容（含文字、圖層效果與遮色片）合成一張 PNG，Unity 端只建立一個 Image 節點，不保留子階層。

什麼時候該用：適合不需要在 Unity 個別操作的背景裝飾、固定組合圖示或複雜視覺效果。什麼時候不要用：若子項需要按鈕事件、換字、動畫、換皮或獨立縮放，請保留原群組階層。工具會一次隔離並合成一個群組，存檔後立即釋放暫存像素層；操作上仍只需按一次 Export。
文字的材質球與描邊想讓 Unity 的字框跟 PS 設計稿一樣

TMP 文字節點自動流程

  1. PS 文字圖層的 Layer Style → Stroke 效果，匯出 JSON 時寫出 outlineColor、outlineWidth 與自動 materialToken。
  2. PS 文字圖層的 Layer Style → Color Overlay 效果，填色顏色寫入 color 欄位，Unity 端套用至 TMP 頂點色。
  3. Unity Generate 時，依序執行材質球解析：
    1. 若設定了「TMP 材質球資料夾」，先掃描資料夾內所有材質球，以 Outline 顏色（RGB 各差 < 8%）為第一條件過濾，再從符合色條件的材質球中選 Thickness 最接近的直接重用，不新增。v2.4.3 改為顏色優先比對，確保不同字號的同色外框都能穩定找到同一顆材質球。
    2. 未找到匹配 → 從預設材質球複製一份，套用 _OutlineColor / _OutlineWidth，儲存至 Assets/Temp/{名稱}/Font/GeneratedMaterials/。
    3. 無 Stroke 資料的文字節點直接套用預設材質球，不做任何處理。
材質球重用邏輯：同一頁面若多個文字用了接近的字框顏色，工具會自動共用同一顆材質球，避免 GeneratedMaterials 資料夾膨脹。

描邊寬度換算 v2.6

PS 描邊 px 換算為 TMP _OutlineWidth（0~1）的公式：

_OutlineWidth = strokePx × samplingPointSize ÷ (atlasPadding + 1) ÷ fontSize
  • samplingPointSize 與 atlasPadding 自動從你指定的 TMP Font Asset 讀取，換字型不需改任何設定。
  • v2.6.0 修正：分母改用 atlasPadding + 1（TMP 的 gradientScale），修正先前描邊系統性偏厚約 20% 的問題。
描邊超限警告 v2.6：SDF 描邊有物理上限（受 atlasPadding 限制）。換算結果超過 1.0 時，Generate 完成後狀態列會顯示超限筆數，Console 列出各節點的描邊 px、目前上限與建議的 atlasPadding。依建議值重建 Font Asset（Window → TextMeshPro → Font Asset Creator，調高 Padding）後重新 Generate 即可。

描邊厚度補償係數 v2.6.2

Importer_v2 視窗的「3. 文字、材質與換皮」區提供一條 描邊厚度補償係數 滑桿（範圍 0.3 ~ 1.5，預設 1.0），值會即時存入 EditorPrefs 跨 session 保留。

正常情況下保持 1.0 不需動。Phase 1 校準實測：當 Unity TMP 用的字型與字重與 PS 設計稿完全一致（例如 PS 用 SourceHanSansTC-Bold、Unity 也烘同名 SDF）時，物理公式直接命中，補償係數 = 1.000 描邊厚度就跟 PS 重合。

什麼情況才需要動補償係數？

  • 換用非思源系列字型（例如圓體、明體、其他廠商 SDF）：不同字型的 antialias falloff 寬度不同，可能視覺上比 PS 偏厚或偏細，這時用校準板回推合適值。
  • PS 與 Unity 故意用不同字型／字重（例如設計稿用 Bold、實際 UI 用 Regular）：補償係數可微調描邊讓比例好看。

校正方法（必要時）：

  1. PS 端執行「Create Calibration PSD」生成 CalibrationBoard.psd，存檔後用 UI Package Exporter 匯出。
  2. Unity Generate 校準板，把 PS 截圖（100% 縮放）丟進 Scene 疊在生成的 UI 上、50% 透明度比對。
  3. Unity 描邊比 PS 偏厚 → 補償係數調低；偏細 → 調高。二分法逼近直到肉眼難辨差異。
  4. 確定後不需再動，所有後續 Generate 自動套用。

係數作用點是公式末端的純倍乘，不影響超限警告的判斷（仍以原始物理寬度為準）。

手動指定材質球

PS 圖層名稱：TXT_title_[MAT:title_yellow_outline]
            TXT_score_[MAT:reward_white_red_outline]

在圖層名稱加上 [MAT:名稱] 標記，Unity 端會優先以此 token 為鍵，從材質球資料夾或 GeneratedMaterials 中尋找對應材質。Unity 端的 Skin Map 也可把 materialToken 對應到不同的 TMP Material Preset。若圖層有 Layer Style 的 Stroke 效果，工具會自動產生 materialToken，無需手動標記。

假厚度標記

在文字圖層名稱加入 [THICK:N]，N 為向下偏移的像素數，Unity 會自動疊兩層 TMP 模擬立體感：

TXT_title_[THICK:3]
TXT_score_[THICK:2]

上層為原始文字，下層為顏色加深（× 0.55）的陰影層，偏移量對應 PS 設計稿像素。同時支援 X 軸偏移：[THICK:2:1]（格式：[THICK:offsetY:offsetX]）。

v2.4 起 PS 端 JSX 已自動解析 [THICK:N] 與 [THICK:N:M]，名稱中加標記即可，不需手動編輯 JSON。
換皮系統：一套新美術套到多個頁面節慶版本、不同主題共用同一套介面

換皮系統提供兩種模式，視情況搭配使用：

模式 A：同名 PNG 覆蓋（舊版，單資料夾）

指定「美術來源資料夾」與「Unity 目標資料夾」，分兩段執行 v2.5.1：

  1. 點「掃描換皮（預覽，不會修改檔案）」：工具比對兩個資料夾，列出「將覆蓋 N 張 / 缺少 M 張」與完整檔名清單，此時不修改任何檔案。
  2. 確認清單無誤後點「確認覆蓋 N 張 PNG」，並在確認對話框按「確定覆蓋」，工具才把新 PNG 覆蓋到 Unity 目標資料夾裡同名的舊 PNG。

適合單一資料夾、檔名相同的換皮情境。找不到對應檔名的圖片會列成待辦清單。掃描後若更改任一資料夾路徑，舊掃描結果會自動作廢，需重新掃描。

此模式只能覆蓋「同名檔案」，若新舊圖檔名不同，或 Sprite 分散在多個 Atlas 裡，請改用 SkinTheme 批次換皮。

模式 B：SkinTheme 批次換皮（推薦）

適合「一套新美術，套用到 10～20 個 Prefab」的情境。以「舊 Sprite → 新 Sprite」為單位定義對應表，工具掃描指定資料夾下所有 Prefab，自動替換符合的 Image.sprite 參照，完全不動任何 Script / Button / Animator / RectTransform。

SkinTheme 使用流程

  1. 在 Project 視窗目標位置 右鍵 → Create → Photoshop UI Importer → Skin Theme，建立 SkinTheme.asset。
  2. 在 Inspector 填入：
    • Target Prefab Folder Asset：將含有目標 Prefab 的資料夾從 Project 視窗拖入此欄位。
    • Entries：每一列填入「舊 Sprite（現在 Prefab 用的）」與「新 Sprite（新美術）」，可加多列。
    • Excluded Prefabs（選填）：不想被換皮的 Prefab 加入此清單。
  3. 在 Importer_v2 面板 → 換皮工具 → 選 SkinTheme → 點「套用換皮到所有 Prefab」。
  4. 確認 Dialog 後工具逐一掃描 Prefab，結果顯示「X 個 Prefab 更新，共替換 Y 個 Sprite」。
注意：套用換皮會直接修改 .prefab 檔案，操作前建議先用 Git commit 備份，或確認可復原。

6. 更新工具

兩邊都是在工具裡按一個鈕就會自己抓新版，不用重新下載、不用重新安裝。

PS　Photoshop 端

開啟 UI Package Exporter，對話框右上角點 Check for Updates。工具會連線 GitHub 比對版本號，確認後自動下載最新 JSX 並覆蓋當前檔案，下次執行即為新版。

v2.5.1 起更新檢查在對話框內執行、不再關閉匯出對話框，已填好的路徑與選項全部保留；只有在實際下載安裝新版時才會關閉（新版需重新執行腳本才會生效）。Windows 用 PowerShell 下載，Mac 用 curl。

Unity　Unity 端

在 Importer_v2 視窗標題列點 從 GitHub 更新工具。工具直接從 raw.githubusercontent.com 下載，不呼叫 GitHub API、不受速率限制；顯示「GitHub 版本 / 本地版本」對比後，確認即自動覆蓋本地，Unity 自動重新編譯。不需要重新複製 PhotoshopUiImporter/ 資料夾。

v2.12.1 下載清單改由倉庫的 update_manifest.txt 決定（出版時自動重生成），新版新增的檔案會一併下載，不會漏檔；manifest 抓不到時退回內建後備清單。

更新後腳本內容會立即覆蓋，Unity 編譯完成前工具暫時無法使用，屬正常現象。

7. 常見問題

安裝器說 installed，但選單裡沒有「PS To Unity v2」？

先確認有沒有把 Photoshop 關掉重開。這個選單只在啟動時掃描一次，裝完當下不會馬上出現。

重開後還是沒有，代表檔案根本沒寫進去。去 C:\Program Files\Adobe\Adobe Photoshop <版本>\Presets\Scripts\ 看有沒有 PS To Unity v2.jsx。沒有的話就是權限被擋，請用系統管理員身分開一次 Photoshop 再跑安裝器（見安裝章節的紅框）。

匯出後有些圖沒有出來？

這些圖層會被跳過：Clipping Mask、Adjustment Layer（色調、曲線等）、名稱有 IGNORE_ / REF_ 的圖層。匯出完的訊息會告訴你跳過了幾張。

PNG 檔名後面多了 _002？

正常的。有兩個圖層同名時，工具會自動加上三位數後綴（layer_002、layer_003…）避免蓋掉彼此。建議在 PSD 裡盡量讓圖層名稱不重複。

按 Generate Prefab 跳出「請先指定預設 TMP Font Asset」？

頁面裡有文字，就一定要在 Unity 端指定一個字型當備援，工具才敢繼續。選一個你專案裡的 TMP Font Asset 即可。

匯入後圖片位置跑掉？

先確認「參考解析度」跟 Canvas 尺寸一致——工具預設會自動讀 layout.json 裡的設定，一般不用動。如果你的 Canvas Scaler 是自訂的，要確認 Match Width or Height 的設定跟 PS 設計稿一致。

圖片已經在 Unity 專案裡了，不想再複製一份？

直接選 Assets 底下的資料夾當 Package 資料夾。工具偵測到圖片已經在專案內時，會直接沿用原路徑，不會重複複製。

PS 端更新後腳本變空白或壞掉？

通常是網路中斷，或 PowerShell 被防毒軟體擋下。請到 GitHub 手動下載最新 JSX 覆蓋：
https://github.com/Wayne188-yiching/PS_To_Unity_v2

Unity 端更新顯示「無法解析 GitHub 回應」？

確認電腦可以連到 api.github.com。部分公司網路會擋 API，這時可從 GitHub 下載 zip，手動覆蓋 Assets/Editor/PhotoshopUiImporter/。

Unity 更新時出現 403 速率限制？

v2.4.3 起已修正：更新不再呼叫 GitHub Contents API（舊版會撞到每小時 60 次上限），改為直接下載。若你用的是舊版工具遇到 403，先手動複製最新 PhotoshopUiImporterWindow.cs 到 Unity，再更新一次即可。

按了「建立專案資料夾」但沒看到 SpriteAtlas？

先確認有填「專案資料夾名稱」再按按鈕。若 Project 視窗沒更新，執行 Assets → Refresh（或按 Ctrl+R）就會出現。

產生後文字顏色不對？

工具讀的是 PS 的 Color Overlay 效果顏色。如果你的文字用的是 Gradient Overlay（漸層），目前版本只支援純色，漸層要等後續版本。

設了材質球資料夾，還是一直新建材質球？

v2.4.3 起是顏色優先比對：先以 RGB 各差 < 8% 篩選候選，再從候選中選 Thickness 最接近的。如果庫裡沒有任何一顆顏色夠接近（差異超過 8%），才會新建。可以檢查一下庫裡材質球的 _OutlineColor 跟 PS 的 Stroke 色差多少。

SkinTheme 換皮後，Prefab 上的 Script / Button 還在嗎？

在。SkinTheme 只改 Image.sprite 這一個欄位，完全不動 Script 序列化欄位、Button onClick、Animator、RectTransform 等任何其他元件。

PS 顯示 36pt，Unity 卻變成 29pt？v2.4.1 已修正

v2.4.0 之前讀的是「設計時原始字體」，不含自由變形的縮放。若文字圖層被縮放過，PS 字元面板顯示的是縮放後的有效字體，兩者就會對不上。v2.4.1 起改讀 impliedFontSize，與 PS 字元面板完全一致。

文字為什麼變成圖片？v2.10.1

預設所有字型都會輸出成可編輯文字。只有這三種情況會變圖片：圖層名稱含 [PNG] / TXTIMG_ 等標記、你在匯出前選取了該文字圖層並勾了對應選項、或你勾了「白名單外字型改為 PNG」。多字型的 PSD 請在 Unity 用 TmpFontMap 把 fontToken 對應到正確字型。

怎麼讓群組自動排列？v2.10.1

在群組名稱加 [H]、[V] 或 [GRID]。v2.10.1 起不再依子層位置自動猜測。若 H/V 子項的交叉軸中心不一致、Unity 固定對齊必然改動 PS 座標，匯出器會輸出 LAYOUT_CROSS_AXIS_DEGRADED 並降級為普通群組；v2.13.3 起連 0.5px 差異也會保護，優先保留設計稿排版。

為什麼加了滑軌標籤反而跑版？v2.13.3

[SCROLL_V]／[SCROLL_H] 群組必須同時包含可捲動內容與直接子層 [SCROLLBAR_*]。如果群組裡只有滑軌、真正內容在外部，工具無法推斷兩者關係；v2.13.3 會輸出 SCROLL_NO_CONTENT 並降級為普通群組，保留 PS 的 Track／Handle 座標。要建立可工作的 ScrollRect，請把內容與滑軌放進同一個 [SCROLL_*] 群組。

如何做 PS 與 Unity 固定解析度逐像素驗收？

使用 PSD 畫布尺寸作為 Prefab 參考解析度，並關閉「啟用響應式 anchor（實驗性）」。該選項是響應式實驗，不是固定解析度的原位重建模式；開啟後巢狀 group 的座標空間可能改變。

  • 問題：PS 的 Save for Web 對相同像素會產生不同 bytes（連檔案大小都不同），因此匯出器那層以「檔案大小 + 尺寸」預篩、再比對 PNG bytes 雜湊的去重常常完全抓不到——候選在預篩階段就被排除，連雜湊都沒算。

  • 群組的直接子圖層標 [MASK]，該層形狀成為整個群組的裁切遮罩；Unity 掛原生 Image + Mask（showMaskGraphic = false），不需要額外 runtime 套件。
  • 沿用 [SCROLLBAR_V] + [TRACK]/[HANDLE] 的「子節點帶 role、父層收編」機制，因此不需要點陣化 PS 圖層遮罩，遮罩圖走既有的一般圖片匯出路徑。[MERGE][MASK] 組合亦可，複合形狀也能當遮罩。

v2.6.3（2026-06-14）— PS 端關閉自動 anchor 推測（hotfix）

  • 問題：先前 inferLayout 會依圖層 bbox 自動推測 anchor（fixed / stretch / 角落）並寫進 layout.json。實測在含群組 effect 的 PSD 上推測結果常常錯誤，會把 331×246 的圖層誤認成 stretch_full、把固定位置的圖層 pivot 標成 (0.5, 0.5) 但 anchor 標成角落，importer 端寫進 RectTransform 之後位置全錯。
  • 修正：inferLayout 一律回傳 center fixed（anchor = pivot = (0.5, 0.5)），所有沒有命名標記的圖層都改用「中心固定 + 原寸 sizeDelta」放置。命名標記（ANCHOR_TL / STRETCH_X / PIVOT_* 等）的 opt-in 響應式行為不受影響，仍由 parseLayoutTag 處理。
  • 影響：所有現有 PSD 需重新執行 UI Package Exporter 才會套用新規則。Unity 端排版會與 PS 設計稿 1:1 對齊；若 Canvas referenceResolution 與 PSD canvas 不一致仍會在 Game View 邊緣裁切，建議把 CanvasScaler 的 referenceResolution 設成與 PSD canvas 相同（例如 2340×1080），或在需要響應式時於 PS 圖層加 ANCHOR_* 命名標記。
  • 已知未修：群組 bounds 受 PS Layer Effect（陰影 / 描邊）影響時會超出父群組或 canvas，需後續單獨修。中心固定模式下子節點位置不受影響，先不動。
